## 1. 系统概述

### 1.1 系统定位

自由报表（FreeReport / 随手报 ReportNow）是一套面向企业总部-部门-分公司三级组织架构的报表填报与审批系统。核心能力包括：

- **模板设计**：支持文本、数字、日期、下拉选择、多行文本及二维交叉表字段；Excel 智能导入建模板（可手动选择表头行、普通表格可强制按交叉表导入）
- **模板审批**：部门创建的模板须经数智化转型办公室审批发布后方可下发
- **周期下发**：按模板向指定分公司下发填报任务，支持一次性下发；月/季/年报可配置周期计划，调度器每日自动生成下发任务
- **数据初始化导入**：按模板批量导入 Excel 填报数据：历史归档直接计入汇总，期初预填生成草稿由经办人核对提交
- **三级审批**：经办人填报 → 复核人审核 → 审批人终审 → 发起部门签收
- **强制收回**：发起部门可强制收回已下发的任务
- **退回提醒**：填报驳回 / 签收退回 / 模板驳回实时提醒（工作台横幅 + 导航角标）
- **智能汇总**：多机构数据横向对比，SQL 下沉聚合，支持 Excel 导出
- **智能问数**：自然语言查询报表数据，自动生成文字结论、图表与数据明细，支持多轮对话与结果下载
- **部门隔离**：严格的部门级数据访问控制

### 1.2 组织模型

```
总部 (headquarter)
├── 业务综合管理部 (department)
├── 办公室 (department)
├── 风险管理部 (department)
├── 数智化转型办公室 (department)   -- 模板审批专属部门
├── 北京分公司 (branch)
├── 上海分公司 (branch)
└── 广州分公司 (branch)
```

| 角色 | 填报 | 审批填报 | 模板管理 | 模板审批 | 下发 | 签收 | 汇总查看 | 智能问数 | 机构管理 |
|------|:----:|:--------:|:--------:|:--------:|:----:|:----:|:--------:|:--------:|:--------:|
| 超级管理员 | - | - | 只读 | - | - | - | 只读 | - | ✓ |

### 4.2 关键设计

**report_submission_data（EAV + 数值冗余）**

- `value` TEXT 存储原始填报值，`row_index=0` 为汇总区、`>0` 为明细行 / 矩阵单元格
- `numeric_value DECIMAL(18,4)` 冗余列（008 新增）：写入时按正则 `^-?[0-9]+\.?[0-9]*$` 同步填充，非数值置 NULL；聚合查询直接 `SUM(numeric_value)`，避免逐行 CAST，并可利用 `idx_sd_numeric (field_id, numeric_value)` 索引

**report_templates.status 生命周期**

```
draft → pending_approval → published ↔ archived
  ↑___________驳回____________|
```

**report_submissions.status 状态机**

```
draft → pending_review → pending_approval → pending_receipt → received
  ↑________驳回 rejected________|        ↑____退回 returned____|
```

## 5. 后端架构

### 5.1 分层职责

| 层 | 职责 | 代表类 |
|----|------|--------|
| Controller | 参数校验、鉴权调用、响应组装 | TemplateController 等 12 个 |
| Service | 业务规则、事务边界（@Transactional） | TemplateService、SubmissionService 等 14 个 |
| Mapper | MyBatis 数据访问（接口 + XML） | TemplateMapper + TemplateMapper.xml 等 9 个 |
| Scheduler | 周期任务调度（@Scheduled cron） | AutoAssignScheduler（每日扫描到期计划自动下发） |
| Entity / DTO | 数据库映射 / 接口契约（SnakeCase JSON） | ReportTemplate、CreateSubmissionRequest |
| security | JWT 认证与授权判定 | JwtAuthFilter、SecurityUtils |
| exception | 领域异常 + 全局错误响应 | DomainException、GlobalExceptionHandler |

### 5.2 认证与授权

- **JwtAuthFilter**：解析 Bearer Token，将 `AuthUser` 写入 SecurityContext
- **SecurityUtils**：通过 `RequestContextHolder` 获取当前请求用户（非构造器注入），提供：
  - `getCurrentUser()` / `isSuperAdmin()` / `isDepartmentReportAdmin()` / `isDigitalAdmin()`
  - `requireSuperAdmin()` / `requireDigitalAdmin()` 等守卫，越权抛 403
  - `canReadTemplate()` / `canReadAssignment()` 等资源级判定（数转办可读全部模板）
- **密码**：BCrypt 哈希；Token 24h 有效期，密钥由 `JWT_SECRET` 配置

### 5.3 部门隔离策略

| 操作 | 超管 | 部门管理员 | 数转办 | 分公司用户 |
|------|:----:|:--------:|:------:|:----------:|
| 读模板 | ✓ 全部 | ✓ 本部门 | ✓ 全部 | - |
| 管理模板 | - | ✓ 本部门 | - | - |
| 审批模板 | - | 提交 | ✓ | - |
| 读任务 | ✓ 全部 | ✓ 本部门发起 + 被下发 | - | ✓ 本机构被下发 |
| 写任务（填报） | - | - | - | ✓ handler/branch_admin |
| 签收 | - | ✓ 本部门 | - | - |

### 5.4 事务与并发

- 多步写操作均在 `@Transactional` 内，失败整体回滚
- 模板编辑、提交、审批等关键路径使用行级锁（`SELECT ... FOR UPDATE`）防并发竞态
- 状态变更前置校验当前状态（如仅 `pending_approval` 可审批），天然幂等

## 6. 前端架构

### 6.1 路由与代码分割

React.lazy + Suspense 懒加载全部页面；受保护路由统一包裹 `ErrorBoundary`（防白屏，含错误提示与刷新按钮）。

### 6.2 数据请求与缓存

- **统一封装** `request<T>()`：注入 Authorization；401 时通过 `window.dispatchEvent(new Event('auth:unauthorized'))` 发出事件，由 App 内 `UnauthorizedHandler` 执行 SPA 内 navigate('/login')，避免硬刷新
- **SWR hooks**：templates / assignments / branches / pendingApprovals / pendingReceipts 等，统一 `revalidateOnFocus: false`，按角色条件请求（`useSWR(cond ? key : null)`）
- **分页**：模板 / 任务列表支持服务端分页（`?page=&size=`），响应 `{ data, total, page, size }`；不传分页参数时保持原数组响应兼容看板类页面

### 6.3 权限控制

`getClientAccess(user)` 返回布尔标志集驱动条件渲染：

```typescript
{
  isSuperAdmin, isDepartmentAdmin, isDigitalAdmin,
  canManageTemplates,     // 模板管理（部门管理员）
  canApproveTemplates,    // 模板审批（数转办）
  canFill, canReceive, canManageOrganizations,
}
```

模板生命周期视图由 `templateLifecycle.ts` 统一计算：`canWrite / canAssign / canSubmitApproval`（draft 可编辑可提交审批、pending_approval 锁定、published 可下发）。

### 6.4 页面清单

| 页面 | 路由 | 功能 |
|------|------|------|
| Dashboard | / | 工作台（待签收、统计、任务、使用帮助） |

### 6.5 Excel 智能导入解析

三处导入能力均为前端 xlsx（SheetJS）解析 + 纯函数模块，逻辑可单测：

| 场景 | 模块 / 组件 | 能力 |
|------|------------|------|
| 模板字段导入（ExcelFieldImportModal） | `utils/excelFieldParser.ts` | 自动跳过标题/落款定位表头，识别明细/交叉表/键值对格式；识别不准可手动选择表头行（下拉 + 点击预览行号）；普通表格可强制按交叉表导入（首列作行维度） |

## 7. 核心业务流程

### 7.1 模板审批流程（数智化转型办公室）

```
部门报表管理员创建模板（draft）
    │
    ▼
模板列表点击「提交审批」── 创建 template_approvals(pending) 记录
    │
    ▼
pending_approval（锁定编辑、禁止下发）
    │
    ├── 数转办「通过」──► published（可下发），审批记录置 approved
    │
    └── 数转办「驳回」──► draft（可修改重提），审批记录置 rejected
```

**约束**：

- 仅 `digital_admin` 可执行通过 / 驳回（`requireDigitalAdmin`），可附审批意见
- 仅 `draft` 可提交审批；`pending_approval` 状态模板编辑、下发均被服务端拦截
- 审批接口校验模板当前状态，重复审批无效

### 7.2 三级审批 + 签收流程

```
经办人填报并提交
    │
    ▼
pending_review → 复核人通过 → pending_approval → 审批人通过 → pending_receipt
                                                                    │
                                                              发起部门签收
                                                                    │
                                                        ┌───────────┴───────────┐
                                                        ▼                       ▼
                                                    received                returned（退回）
```

任意审批环节可驳回（`rejected`），经办人修改后重新提交，流程从头开始。

### 7.3 强制收回流程

```
发起部门管理员 → 选择未汇总任务 → 填写收回原因 → 确认收回
    │
    ▼
任务状态 → recalled
    ├── 写入 assignment_recalls 审计表
    └── 取消相关 pending 审批记录（标记 rejected）
```

**约束**：仅发起部门管理员可收回；已汇总（aggregated）任务不可收回；不可重复收回；原因必填。

### 7.4 一次性下发

下发时勾选「一次性下发」→ `period_label` 追加唯一时间戳后缀（如 `2026年07月 #1784862420000`），`is_one_time=1`，绕过 `uq_assignment_period` 唯一约束。适用于补充调查、临时加报。

### 7.5 周期计划自动下发

```
部门管理员 → 模板卡片「周期计划」→ 启用并配置（下发日、截止偏移天数、目标分公司）
    │
    ▼
report_template_schedules（每模板一条，uq_schedule_template）
    │
    ▼
AutoAssignScheduler 每日 06:30 扫描（cron 可配置 app.auto-assign-cron）
    │
    ▼
AutoAssignService：周期标签缺失/重复 → 等待 / 已生成；到期日未到 → 等待；
到期且未生成 → 按 target_company_ids 批量创建下发任务（含 deadline）
```

- 周期标签由 PeriodLabelService 统一计算（月报 `YYYY年MM月`、季报 `YYYY年第N季度`、年报 `YYYY年`），与 `utils/periodSchedule.ts` 前端口径一致
- `last_period_label` 防重复生成；自动下发前校验模板状态为 published、周期标签唯一
- 支持「立即生成本期」手动触发（POST /api/templates/:id/schedule/run），与调度器共用同一套幂等逻辑
- 规则：月报每月 N 日、季报每季首月 N 日、年报指定月 N 日（1-28）；下发后 M 天为填报截止日

### 7.6 数据初始化导入

```
部门管理员 → 模板卡片「数据导入」→ 上传 Excel → 列映射 + 行状态预览 → 选择导入方式
    │
    ├── 历史归档 → DataImportService.importAsArchive
    │      └── 直接生成 received 状态填报（计入汇总），逐分公司行级事务
    └── 期初预填 → DataImportService.importAsPrefill
           └── 生成 draft 草稿，经办人核对后走正常三级审批流
```

- 仅 `department_admin` 可操作；模板须含明细或交叉表字段；`canManageTemplate` 校验模板归属
- Excel 由前端解析为映射后的行数据（`dataImportMapping.ts`），后端按「分公司编码 → 机构」映射写入
- 归档模式自动创建/复用对应周期下发任务并置为 aggregated 可见；预填模式校验当前周期已存在任务

### 7.7 汇总逻辑

- 按模板 + 周期筛选下发任务，取每个任务的最新版本已批准填报（状态 ∈ pending_receipt / received）
- **SQL 下沉聚合**：`SUM(d.numeric_value)`、`COUNT(DISTINCT s.id)` 在数据库层完成，替代 Java 内存 Stream 聚合
- 明细行合并展示；仅已审批通过的填报计入统计
- 支持 Excel 导出（机构对比表 + 明细表 + 进度表）

### 7.8 智能问数流程

```
部门管理员输入自然语言问题（支持多轮对话上下文）
    │
    ▼
AiQueryService：单用户并发限 1（防止重复点击）
    │
    ▼
构建用户可见的模板上下文（已发布模板 + 有数据的周期 + 指标列表）
    │
    ▼
AiClient 调用大模型：解析问题 → 生成结构化查询计划（JSON）
    │
    ▼
计划校验：模板、指标、周期必须落在当前用户可见范围内
    │
    ▼
复用 AggregationService 权限校验路径取数（不生成 SQL，走已有聚合引擎）
    │
    ▼
AiClient 二次调用大模型：总结数据 → 生成文字结论
    │
    ▼
返回：answer（结论）+ chart（图表数据）+ table（明细表格）+ plan（查询计划）+ scope_note（口径说明）
```

**安全设计**：

- 大模型只负责「理解问题」与「总结数据」，不生成 SQL，取数一律走 AggregationService 的权限校验路径
- 计划校验确保模板 ID、指标字段、周期标签均在当前用户可见范围内，防止越权取数
- 单用户并发限 1（`inFlightUsers` 集合），防止 LLM 调用慢且贵被重复点击打爆
- 审计日志记录谁在什么时候问了什么、命中了哪张表哪些周期、耗时多少

**前端展示**：

- 图表区按后端给定的 chart_type 渲染柱状图 / 折线图 / 饼图（recharts）
- 数据明细表默认折叠，点击展开核对口径
- 结果下载为 Excel（三个 Sheet：查询说明 + 查询数据 + 图表数据）
- 建议问题推荐（根据用户可见模板与周期自动生成）

**限制**：

- 单次查询最多涉及 12 个周期、6 个指标
- 交给模型总结的数据行上限 50 行
- 多轮对话携带最近 6 轮历史
- 仅统计已提交并通过接收的数据（pending_receipt / received）

## 8. 权限与安全

### 8.1 认证机制

- **密码存储**：BCrypt 哈希，不可逆
- **Token**：JWT，24h 有效期，生产环境强制配置 `JWT_SECRET`
- **传输**：Bearer token via Authorization header

### 8.2 请求安全

- **CORS 白名单**：`CORS_ORIGINS` 配置允许的源
- **SQL 注入防护**：MyBatis 参数化查询
- **错误屏蔽**：GlobalExceptionHandler 统一出口，500 返回通用文案，不泄露堆栈
- **参数校验**：DTO 层 jakarta.validation（@NotNull 等），400 返回字段级错误

### 8.3 并发安全

- **悲观锁**：模板 / 任务 / 填报写操作 `SELECT ... FOR UPDATE`
- **事务**：所有多步写操作 `@Transactional`，失败自动回滚
- **幂等性**：模板启停、审批、状态变更前置检查当前状态

### 8.4 数据隔离

通过 `owner_department_id` / `issuer_department_id` / `assigned_to_company_id` 三字段 + SecurityUtils 资源级判定实现：

- 部门管理员仅访问本部门模板和本部门发起的下发任务
- 数智化转型办公室可读全部模板，仅可执行模板审批
- 分公司用户仅访问本机构被下发的任务
- 超级管理员全局只读，机构与用户管理可写

### 8.5 改进建议

- **速率限制**：登录等敏感端点建议添加防暴力破解保护
- **审计日志**：建议扩展审计表覆盖所有状态变更操作

## 9. 性能优化

### 9.1 数据库优化

| 优化项 | 说明 |
|--------|------|
| numeric_value 冗余列 | 聚合免逐行 CAST，`idx_sd_numeric` 索引加速 |
| SQL 下沉聚合 | SUM / COUNT 在 SQL 层完成，避免全量明细回传 |
| 列表分页 | 模板 / 任务列表 `LIMIT ? OFFSET ?`，避免全表加载 |
| 性能索引 | 006 迁移补充 submissions / approvals 复合索引 |
| 批量查询 | IN 查询 + Map 关联，消除 N+1 |
| 悲观锁 | FOR UPDATE 防并发竞态 |

### 9.2 后端优化

| 优化项 | 说明 |
|--------|------|
| HikariCP 连接池 | Spring Boot 默认，复用连接 |
| DTO SnakeCase 序列化 | Jackson @JsonNaming 统一命名策略 |
| 全局异常处理 | 统一错误响应，避免异常穿透 |

### 9.3 前端优化

| 优化项 | 说明 |
|--------|------|
| 代码分割 | React.lazy 全页面懒加载 |
| SWR 缓存 | 统一 hooks，`revalidateOnFocus: false` |
| 条件请求 | 按角色条件加载，减少不必要请求 |
| ErrorBoundary | 局部错误不扩散为整页白屏 |
| 401 事件总线 | SPA 内跳转替代 window.location 硬刷新 |
