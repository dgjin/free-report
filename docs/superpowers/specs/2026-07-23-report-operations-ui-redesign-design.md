# 下发管理与汇总报表界面重设计

## 背景

当前“下发管理与状态跟进”逐条展示任务，缺少异常概览、组合筛选和报表整体进度；总部管理员需要逐项阅读才能发现逾期、退回或未填报机构。当前“总部多维汇总报表”将指标卡、机构对比和全部明细连续铺开，页面过长，表格层级和主要操作不够明确。

本次仅重新组织现有任务、截止日期、提交状态、汇总值、平均值和明细数据。不会新增同比、环比、业务阈值或自动预警规则。

## 目标与用户

主要用户是总部部门报表管理员。进入下发管理页后，应在五秒内发现需要处理的异常机构，并能快速完成签收、退回或进入对应周期汇总。

超级管理员可以查看全部下发与汇总数据，但保持只读。分公司用户继续使用填报任务视图，不获得总部管理操作。

## 视觉与交互原则

- 使用白色卡片、浅灰页面背景和紧凑间距，降低装饰性元素数量。
- 红色只表示异常，黄色表示待处理，蓝色表示流转中，绿色表示已完成。
- 每个任务行只保留一个主要操作；次要操作放入详情或弹窗。
- 表格表头保持清晰，数值右对齐，状态使用短标签，不使用中英文混排标题。
- 桌面端使用宽表格；移动端将任务行转为信息卡，指标卡按两列或单列排列。
- 所有筛选、页签和弹窗可通过键盘操作，并提供清晰的焦点状态。

## 下发管理与状态跟进

### 页面结构

页面从上到下分为四层：

1. 标题与操作区：标题、简短说明、搜索框、报表和周期筛选；部门管理员显示“新建下发”，超级管理员不显示写操作。
2. 状态概览：异常、待填报、待签收、已完成四张可点击数字卡。点击卡片直接应用对应筛选。
3. 需处理任务：默认优先显示异常和临近截止任务，按严重程度、截止日期升序排列。
4. 报表进度：按模板和周期分组，展示已完成机构数、总下发机构数、进度条和“查看汇总”入口。

### 互斥状态分类

每个任务只进入一个概览分类，避免统计数字重复：

- 已完成：`received`、`approved` 或 `aggregated`。
- 异常：`returned`、`rejected`，或未完成且截止日期早于当天。
- 待签收：`pending_receipt`。
- 待填报：其余未完成状态，包括 `pending`、`filling`、`submitted`。

“需处理任务”包含异常任务，以及三天内截止的待填报任务。待签收任务独立显示在待签收筛选中，避免将正常等待签收误标为异常。

### 搜索与筛选

- 文本搜索匹配报表名称、任务标题、机构名称和机构编码。
- 状态概览卡、报表筛选和周期筛选可以组合使用。
- “清除筛选”恢复默认的需处理视图。
- 无匹配结果时显示当前筛选条件和清除按钮，不显示空白页面。

### 任务行

任务行固定展示机构、报表及周期、截止日期、状态和一个主要操作：

- 异常或待填报：查看任务。
- 待签收且当前用户是所属发起部门报表管理员：签收处理。
- 已完成：查看汇总。
- 超级管理员：仅显示查看任务或查看汇总，不显示签收和退回。

### 当前页签收

部门管理员点击“签收处理”后打开弹窗，复用现有待签收列表与签收接口。弹窗展示报表、机构、周期、版本、提交人、提交时间和备注，并提供“查看完整填报内容”入口。现有待签收查询响应补充周期和提交人姓名，不新增接口。

- 确认签收：二次确认后提交 `received`。
- 退回修改：必须填写原因后提交 `returned`。
- 成功后关闭弹窗，并刷新概览数字、任务列表和报表进度。
- 失败时保持弹窗和退回原因，显示接口错误并允许重试。
- 签收中心继续保留，两处操作共享相同后端权限和状态校验。

## 汇总报表

### 页面结构

汇总页采用“概览 + 页签”：

1. 标题区：模板、周期、已统计机构数、模板和周期切换、复制或导出操作。
2. 指标概览：每个数值型汇总字段一张卡，展示合计、平均值和计入统计的机构数；额外展示未统计机构数。
3. 内容页签：机构对比、明细数据、填报进度。

### 机构对比页签

- 默认页签。
- 展示实际下发机构、填报状态和汇总字段。
- 支持机构搜索。
- 表格底部固定展示数值字段合计。
- 未签收机构保留在表格中，字段显示短横线，不进入数值统计。

### 明细数据页签

- 展示已签收机构的合并明细行。
- 支持机构搜索。
- 数值字段底部展示小计。
- 无明细字段或无已签收明细时显示明确空状态。

### 填报进度页签

- 按状态分组展示实际下发机构。
- 展示机构、任务状态、版本和截止日期。
- 该页签只用于查看，不新增催办或通知功能。

### 页面状态

- 初次加载显示与最终布局一致的骨架屏。
- 请求失败显示错误说明和“重新加载”按钮，不保留旧模板的数据冒充新结果。
- 模板无下发周期时禁用周期选择，并显示“该模板暂无下发任务”。
- 汇总数据为空时仍显示模板和周期上下文，以及零值概览和空状态。

## 组件与数据边界

新增纯前端视图模型工具，负责：

- 任务状态分类、异常判断和默认排序。
- 文本、状态、模板和周期组合筛选。
- 按模板与周期计算报表进度。
- 汇总页签状态和机构搜索。

页面组件拆分为状态概览、任务筛选栏、任务表、报表进度卡、签收弹窗、汇总指标卡和汇总页签。现有 `/api/assignments`、`/api/receipts/pending`、`/api/receipts/:id/action` 和 `/api/aggregations/by-template/:templateId` 接口继续使用；`/api/receipts/pending` 仅扩展 `period_label` 和 `submitted_by_name` 字段，不修改数据库结构。

## 测试与验收

### 自动化测试

- 状态分类互斥且覆盖全部任务状态。
- 逾期、退回和三天内截止任务的排序正确。
- 搜索和组合筛选正确。
- 报表进度按模板和周期分组。
- 部门管理员与超级管理员的操作权限正确。
- 签收成功刷新数据，退回缺少原因时不提交，请求失败保留输入。
- 汇总三个页签仅渲染当前内容，机构搜索和空状态正确。
- 响应式关键结构和可访问性属性存在。

### 人工验收

- 部门管理员可在五秒内定位异常任务。
- 可从待签收任务完成签收或退回，并看到状态即时更新。
- 可从报表进度进入对应模板和周期的汇总。
- 汇总页首屏不出现长明细表；切换页签后可完整查看机构对比、明细和进度。
- 超级管理员可查看但无法执行签收、退回或新建下发。
- 桌面和窄屏下主要操作均可见且无需横向滚动任务列表。
