# 总部部门报表隔离与签收流程设计

## 1. 目标

在现有总部与分公司组织结构中增加总部部门，使各部门能够独立设计、管理和下发本部门报表。部门之间的模板严格隔离；接收机构只能处理分配给自己的填报任务。提交内容固定返回发起部门，由发起部门报表管理员签收或退回。超级管理员拥有全局只读审计能力，但不能执行任何业务写操作。

本功能以已完成的“报表停用与重新启用”功能为基础。实施前先将 `feat/template-disable` 合并到 `main`，再创建新的隔离开发分支。

## 2. 组织模型

复用统一机构表 `companies`，将机构层级扩展为：

- `headquarter`：总部根机构。
- `department`：总部部门，父机构为总部。
- `branch`：分公司，父机构为总部。

首批预置以下部门：

- 办公室。
- 业务综合管理部。
- 计划财务部。
- 风险管理部。

超级管理员可以新增和停用总部部门。已被用户、模板或任务引用的部门不能物理删除。部门停用后不能创建模板、接收新任务或作为新下发目标，历史数据继续可读。

## 3. 用户与角色

用户仍归属于唯一机构。新增角色 `department_report_admin`，一个部门可以配置多名报表管理员。

### 3.1 超级管理员

- 维护机构、用户和部门报表管理员配置。
- 查看所有模板、任务、提交、签收记录及操作日志。
- 不能创建、编辑、停用或下发模板。
- 不能填报、提交、签收或退回。
- 所有业务写接口必须返回 `403`，不能沿用当前超级管理员自动获得写权限的规则。

### 3.2 部门报表管理员

- 仅查看和管理所属部门的模板。
- 创建、编辑、停用、重新启用和下发本部门模板。
- 查看本部门发起任务的进度、提交内容和汇总结果。
- 签收或退回提交到本部门的报表。
- 可以处理下发给自己部门的填报任务。

### 3.3 普通经办人员

- 仅查看下发到自己所属机构的任务。
- 保存草稿、提交、修改被退回的内容并重新提交。
- 不能进入模板库或模板设计页。
- 不能查看其他接收机构的填报数据。

现有分公司角色暂时保留，用于兼容历史账号。分公司 `handler` 和 `branch_admin` 继续具有本机构任务填报能力，但不获得总部部门模板管理或签收权限。

## 4. 报表与任务归属

### 4.1 模板归属

`report_templates` 增加非空 `owner_department_id`，指向启用中的总部部门。模板只能有一个所属部门。

模板读取规则：

- 部门报表管理员只能读取本部门模板。
- 其他部门不能查看模板列表、模板详情或设计字段。
- 接收任务不会授予模板库访问权。
- 超级管理员可以只读查看全部模板。

模板写入规则：

- 仅模板所属部门的报表管理员可以写入。
- 超级管理员及其他部门管理员均返回 `403`。
- 模板必须为 `published` 且所属部门启用，才能编辑或下发。

### 4.2 下发归属

`report_assignments` 保留 `assigned_to_company_id` 作为统一接收机构，并增加非空 `issuer_department_id`，固定记录发起部门。该快照不因创建人调动、管理员变更或部门改名而改变。

合法接收目标为启用中的总部部门或分公司。发起部门可以下发给其他总部部门和分公司；不允许下发给总部根机构、停用机构或自身部门。

## 5. 提交与签收状态流

1. 部门管理员下发模板，每个接收机构生成独立任务。
2. 接收机构经办人员保存草稿并提交。
3. 提交后进入 `pending_receipt`（待签收），只能出现在发起部门签收中心。
4. 发起部门报表管理员执行：
   - `received`（已签收）：流程完成，记录签收人、时间和意见。
   - `returned`（已退回）：记录退回原因，接收机构可以修改并重新提交。
5. 重新提交后再次进入待签收。

签收使用数据库事务和行锁。多名部门管理员并发操作同一提交时，只允许第一个合法状态转换成功，不能产生重复签收结果。

新增签收记录表，记录提交、发起部门、操作人、结果、意见及时间。一个提交版本最多有一个生效签收结果；退回后重新提交产生新版本和新的签收记录。

现有经办人、复核人、审批人三级审批不用于部门自定义报表的新流程。历史审批数据保留只读，不删除。

## 6. 权限边界

所有授权由后端根据数据库中的当前用户、机构归属、模板归属、任务接收机构和发起部门计算，不信任 Token 中的旧机构信息，也不依赖前端隐藏按钮。

### 6.1 模板

- 列表查询在 SQL 层按所属部门过滤。
- 详情、字段新增、字段停用、基础信息修改、模板启停和下发均重复校验所属部门。
- 所有校验与写入在同一事务中完成，防止归属或状态并发变化造成越权。

### 6.2 任务与提交

- 接收机构成员可以读取本机构任务。
- 仅接收机构的合法经办角色可以保存或提交。
- 发起部门管理员可以读取本部门发起任务及其提交内容，但不能代替接收机构修改数据。
- 超级管理员仅可读取。

### 6.3 签收

- 仅任务 `issuer_department_id` 对应部门的报表管理员可以签收或退回。
- 接收部门管理员、其他部门管理员、分公司人员和超级管理员均不能签收。

对伪造模板 ID、任务 ID、提交 ID、字段 ID、签收 ID 和跨机构组合参数统一返回 `403` 或 `404`，不得泄露其他部门资源是否存在。

## 7. 数据库迁移

新增版本化、事务化迁移：

1. 扩展机构层级枚举和用户角色枚举。
2. 预置四个总部部门。
3. 为模板增加 `owner_department_id`。
4. 为任务增加 `issuer_department_id`。
5. 扩展提交和任务状态。
6. 创建签收记录表、唯一约束、查询索引和外键。
7. 将现有模板及历史任务归入“业务综合管理部”。
8. 保留现有提交、审批和汇总数据，并建立一致的历史归属。
9. 完成回填后再将新增归属字段设为非空。

迁移脚本通过 `schema_migrations` 防止重复执行。迁移前后必须校验模板、任务、提交和数据行数一致，并验证不存在空归属或失效外键。

## 8. 页面与导航

### 8.1 机构管理

仅超级管理员可访问：

- 管理总部部门和分公司。
- 新增、停用机构。
- 管理用户所属机构。
- 设置或取消部门报表管理员。

### 8.2 我的报表

部门报表管理员仅看到本部门模板。模板卡片、设计页、停用和下发操作沿用模板生命周期规则。超级管理员进入时为全局只读视图。

### 8.3 收到的任务

部门和分公司经办人员仅看到分配给本机构的任务。页面显示报表名称、发起部门、周期、截止时间和当前状态，不显示模板设计入口。

### 8.4 下发管理

部门报表管理员查看本部门发起的所有接收机构进度，可进入提交详情，但不能修改接收方数据。

### 8.5 签收中心

仅部门报表管理员访问，默认显示本部门待签收提交，支持查看内容、签收和退回。操作期间按钮进入忙碌状态，避免重复提交。

### 8.6 全局查看

超级管理员按发起部门、模板、接收机构、周期和状态筛选所有业务数据。所有表单及操作控件只读。

## 9. 错误处理与审计

- 未认证返回 `401`。
- 已认证但越权返回 `403`。
- 当前用户有权访问但资源不存在返回 `404`。
- 非法状态转换或并发冲突返回 `409`。
- 数据库事务失败时整体回滚，不保留部分任务或部分签收记录。

记录以下审计事件：机构新增/停用、用户调动、部门管理员设置/取消、模板创建/修改/启停/下发、提交、签收和退回。审计记录包含操作人、所属机构、资源类型、资源 ID、动作和时间，不记录密码或完整报表敏感内容。

## 10. 测试与验收

- 四个预置部门创建成功，机构树层级正确。
- 一个部门支持多名报表管理员。
- 两个部门之间模板列表、详情和写操作完全隔离。
- 接收部门只能看到任务，不能查看或管理源模板。
- 分公司与总部部门均可作为合法接收目标。
- 停用机构不能创建模板、接收任务或作为下发目标。
- 提交只能由任务接收机构执行。
- 签收和退回只能由任务发起部门管理员执行。
- 退回后原接收机构可以修改并重新提交。
- 并发签收只产生一个有效结果。
- 超级管理员可读取全部业务数据，所有业务写接口返回 `403`。
- 伪造跨部门资源 ID 无法绕过权限。
- 历史模板、任务、提交、审批、汇总和明细数据迁移后仍可读取。
- 数据迁移可重复执行且不会重复创建部门或签收数据。
- 全量测试、TypeScript 检查、生产构建和本地 MySQL 冒烟验证通过。
