# 按下发机构范围汇总设计

## 背景

总部多维汇总接口当前先读取全部启用中的分公司和总部部门，再尝试匹配指定模板、指定周期的下发任务。因此，“各分公司汇总指标对比网格”会显示没有收到该报表的机构，机构总数也会包含这些无关机构。

## 目标

- 汇总范围以指定模板、指定周期的实际下发任务为唯一依据。
- 实际收到报表的分公司和其他总部部门都显示在对比网格中。
- 未收到报表的机构不显示，也不参与机构总数、合计、平均值或明细汇总。
- 已下发但尚未提交或签收的机构仍显示，其数据不进入数值统计。
- 历史汇总保留下发时的机构范围；机构后来停用时，其历史任务仍可查看。

## 设计

### 数据范围

后端继续使用 `selectAssignmentsForPeriod` 按模板 ID 和周期筛选任务。汇总循环改为遍历筛选后的任务，而不是遍历全量机构。

每个任务通过 `assigned_to_company_id` 查找目标机构，并生成一条 `company_data`。数据库唯一约束 `uq_assignment_period` 保证同一模板、机构和周期至多存在一个任务。

若任务引用的机构记录异常缺失，则跳过该任务，避免返回无法识别的机构行；正常的已停用机构仍保留，因为机构查询不按启用状态过滤。

### 数据统计

每个实际下发任务继续读取该任务最新的已签收或已审批版本：

- 存在有效提交时，填充汇总指标和明细行，并计入数值字段的合计、数量和平均值。
- 不存在有效提交时，保留机构行并显示未完成状态，不计入数值统计。

前端无需再次过滤机构。页面中的“已统计 X / Y 个机构”直接使用后端返回的 `company_data`，因此分母只代表实际下发机构。

### 展示文案

网格仍保留现有标题。统计单位从“分公司”调整为“机构”，以覆盖总部部门下发目标。

## 错误与边界处理

- 模板不存在、无权查看或未选择周期的现有错误处理保持不变。
- 指定周期没有下发任务时，返回空的 `company_data`、空明细和零值统计。
- 未提交任务显示在网格中，但不进入指标合计和平均值。
- 停用机构的历史任务仍显示，不依赖当前机构启用状态。
