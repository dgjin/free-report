## Phase 4：Express → Spring Boot 架构迁移 (2026-07-24)

### 修改思路
原 Express (Node.js) 后端在生产稳定性、事务管理、类型安全方面存在瓶颈。全面迁移至 Spring Boot 3.3.2 + MyBatis + Java 17 架构，获得声明式事务（@Transactional）、连接池（HikariCP）、全局异常处理等企业级能力。

### 关键提交
| 提交 | 说明 |
|------|------|
| `3342720` refactor: 清理旧 Express 后端，引入 Spring Boot 新架构 | 架构迁移里程碑 |
| `6bbabed` fix: 修复汇总报表接口返回结构与前端契约不匹配导致的页面崩溃 | 契约对齐 |
| `4d668e7` fix: 修复多行明细聚合丢行与汇总字段域混入，补强接口契约校验 | 聚合修复 |

### 核心产出
- **Spring Boot 后端**：13 个 Controller、17 个 Service、9 个 Mapper
- **MyBatis ORM**：注解 + XML 混合，SnakeCase JSON 序列化
- **声明式事务**：`@Transactional` + `SELECT ... FOR UPDATE` 悲观锁
- **全局异常处理**：`DomainException` + `GlobalExceptionHandler`
- **连接池**：HikariCP，生产级数据库连接管理
- **Express 历史保留**：`express-backend` 分支存档

## Phase 9：智能问数核心功能 (2026-07-31)

### 修改思路
引入 AI 大模型能力，让用户可以用自然语言查询报表数据。采用"双阶段 LLM"架构：第一阶段理解问题生成结构化查询计划，第二阶段总结数据生成文字结论。取数不走 SQL 而是复用已有的 AggregationService 权限校验路径，确保数据安全和口径一致。

### 关键提交
| 提交 | 说明 |
|------|------|
| `e3fa994` feat: 智能问数（自然语言查报表）——双阶段 LLM + 白名单校验 + 聚合引擎取数 | 里程碑提交 |

### 核心产出
- **双阶段 LLM 架构**：
  - 阶段一：理解问题 → 生成 JSON 查询计划（模板/周期/指标/分组）
  - 阶段二：总结数据 → 生成文字结论 + 图表建议
- **白名单校验**：`AiQueryContextBuilder` 按用户可见模板构建上下文，防止越权取数
- **聚合引擎取数**：复用 `AggregationService`，不生成 SQL
- **运营统计直答**：规则识别先于 LLM（"各部门下发情况"直接 SQL 统计，不消耗模型调用）
- **前端**：AiQuery 页面（自然语言输入 + 图表 + 数据明细 + 建议问题）
- **测试**：27 项 JUnit 测试 + 3 个前端契约测试
- **评估脚本**：`scripts/ai-query-eval.ts` 自动化评估问数质量

### 核心产出
- **8 层纵深安全防御**：

| 层 | 机制 | 说明 |
|----|------|------|
| 输入层 | `sanitizeQuestion()` | 长度截断 500 字 + 协议标记正则过滤 + 70% 阈值拒绝 |

| 历史层 | `sanitizeHistory()` | assistant 丢弃 + user 截断 + 协议标记过滤 |
